## 1. 业务背景与使命

数据结构与算法是计算机科学的核心基石。传统教学中，学生通常面临“静态伪代码抽象”、“动态指针与数组交换过程缺乏直观具象化”、“学习遇到阻碍时无人指导”的三大困境。

**衍序 · AlgoFlow 的核心使命**：
以**“推衍秩序 · 步进数据心流”**为指引，融合**高帧率算法可视化演练**、**领域感知 RAG 大模型导师**与**shadcn/Radix 极简交互**，打造从“感性认知”到“理性推导”，再到“工程实践”的一体化交互教学平台。

## 3. 功能性需求规格 (Functional Requirements)

### FR-01: 核心排序算法动态演练工作台 [已确认]
* **FR-01.1 全量 19 种排序算法**：支持冒泡、选择、插入、希尔、快速、归并、堆、计数、桶、基数排序等基础与衍生算法。
* **FR-01.2 状态机控制**：提供播放/暂停、单步前进（Step Next）、单步后退（Step Prev）、调速滑块（0.25x ~ 4.0x）、重置。
* **FR-01.3 多形态数据集**：支持随机分布、近乎有序、完全逆序、大量重复及用户自定义合法数组输入（3~30 项）。
* **FR-01.4 指针与动态高亮**：以语义 token 和具名文字区分比较、移动、基准值与已排序；局部蓝色仅用于当前执行状态，不依赖颜色单独传达含义。
* **FR-01.5 性能指标实时演算**：动态累加显示比较次数、交换次数、当前步骤及时间复杂度对标。

### FR-02: 领域感知 RAG 增强型 AI 导师 [已确认]
* **FR-02.1 步骤快照自动挂载**：提问时自动挂载当前算法类型、步骤下标、数组快照与高亮伪代码行号。
* **FR-02.2 权威知识库切片检索 (RAG)**：基于 19 篇官方排序教研专章向量化切片，混合检索召回 Top-3 切片，幻觉率 < 2%。
* **FR-02.3 流式打字机答疑 (SSE)**：采用 Server-Sent Events 流式生成，首字 TTFB < 1200ms，支持 LaTeX 与代码块排版。
* **FR-02.4 答案引用溯源**：生成结果末尾附带知识库章节溯源卡片，支持用户一键定位深入阅读。

### FR-03: 算法知识库与学习路径 [已确认]
* **FR-03.1 19 篇官方教研文档**：涵盖原理、时空几何推导、伪代码、多语言实现与工业实践（TimSort 等）。
* **FR-03.2 学习路径导航**：提供新手进阶图谱与综合对比矩阵。
* **FR-03.3 全局混合搜索**：基于 Elasticsearch 的全站知识多路检索。

### FR-04: 社区交流与题解互动 [已确认]
* **FR-04.1 图文题解发布**：在线 Markdown 编辑器、实时双向预览与草稿暂存。
* **FR-04.2 点赞与评论互动**：支持文章轻量点赞、层级评论。

### FR-05: 用户认证与个人中心 [已确认]

本节为登录注册与账户能力的当前需求；实施状态见 BACKLOG `TSK-205`。当前邮箱密码方案已在既有本机环境实现并完成限定流程验收；接口、迁移和运行边界见 HANDOVER。旧 OTP / GitHub 入口已移除，历史供应商验证不计入新认证验收。

* **FR-05.1 邮箱密码登录**：登录字段为邮箱、密码。移除 GitHub 和其他第三方入口，不以邮箱验证码作为登录方式。邮箱去除首尾空白并按统一规则归一化，密码保持原值、不得自动 trim；允许粘贴和密码管理器填充。失败使用统一提示「邮箱或密码不正确」，不泄露账户是否存在；限流和服务故障分别给出可重试说明。
* **FR-05.2 独立注册流程**：从同一弹窗的「注册」进入，字段为邮箱、密码、确认密码；密码长度为 8–64 个字符，前后端规则必须一致，不强制拼凑字符类型。注册前展示规则，确认密码仅作一致性校验、不持久化。注册成功显示确认态并进入登录，保留邮箱、清空密码；只有真实登录成功后才能建立会话，不把注册回执当作已登录。
* **FR-05.3 注册状态与验证边界**：同邮箱重复提交受服务端唯一约束，遇到未知网络结果需先确认结果再重试，不能重复建号。邮箱密码注册不能自动标为邮箱已验证；邮箱所有权验证与找回密码是独立能力，未接通前不展示无效链接。本轮不设计第三方绑定、验证码倒计时或默认密码。
* **FR-05.4 弹窗与上下文**：所有登录入口使用共享 Dialog，显式展示已确认 Logo A 与「衍序 AlgoFlow」。登录 / 注册切换保留邮箱、清空密码与错误；密码默认隐藏，可通过具名图标按钮显示 / 隐藏。提交中禁用重复操作并标明当前动作；关闭后清除密码，旧请求不能重开弹窗或回写新表单。成功后继续原 URL、演练步骤或编辑上下文，只接受站内返回目标。
* **FR-05.5 会话与角色**：沿用网关与 Sa-Token 会话；注册只能获得普通学习者角色。管理员由服务端受控授权，注册表单不提供角色选择。头像菜单进入个人中心、账户设置、通知中心；仅管理员看到运营管理，直接请求仍须服务端鉴权。退出、账号停用、删除及敏感凭证变更须撤销相应会话，401 清理前端身份并保留当前 URL。
* **FR-05.6 个人资料与账户安全**：公开资料仅含昵称、头像、简介与公开内容；登录邮箱、密码和会话信息不出现在公开主页。账户安全显示具名邮箱、验证状态与「邮箱密码」方式，密码只能重设、不能回显。修改密码需验证当前密码并校验新密码 / 确认密码；成功后撤销旧会话并要求重新登录。改邮箱需单独验证所有权，不与普通资料保存混用。
* **FR-05.7 存储与迁移**：密码使用专用不可逆哈希和独立盐，不存储明文、可逆值或无盐摘要；请求、审计、埋点、草稿和浏览器持久存储不得记录密码。原有验证码 / 第三方账户不得被赋予公共默认密码；安全设置密码、账户兼容和回滚方案须在实施前明确，设计完成不代表旧账户已迁移。
* **FR-05.8 个人工作区**：继续学习、学习记录、我的内容、收藏、通知与设置沿用共享 Layout；账户数据按用户隔离。学习进度、偏好或草稿在本地保存时须如实标注，不能宣称已服务端跨设备同步；不以装饰勋章或虚构计数代替真实业务。

### FR-06: 统一运营与切片管理后台 [已确认]
* **FR-06.1 统一内嵌架构**：严格统一置于 `frontend/src/app/admin/`，严禁独立工程。
* **FR-06.2 知识库切片管理**：基于 Flexmark AST 的分块微调、向量同步与召回评测实验室。
* **FR-06.3 安全审计**：API 访问日志与异常告警追踪。

## 4. 非功能性需求规格 (Non-Functional Requirements)

* **NFR-01 帧率与动效流畅度**：GSAP 动画硬件加速渲染，主流设备稳定保证 **60 FPS**（掉帧率 < 1%）。
* **NFR-02 交互延迟 (INP)**：演练控制器（步进/暂停等）操作响应延迟 **≤ 100ms**。
* **NFR-03 首屏加载 (LCP)**：前台页面最大内容渲染时间 **LCP ≤ 1.5s**。
* **NFR-04 视觉与无障碍 (a11y)**：严格遵循 docs/DESIGN.md 的 shadcn/Radix 黑白灰语义 token、单层顶部布局与无装饰边框，文本与图表对比度满足 **WCAG 2.1 AA** 标准（对比度 ≥ 4.5:1）。
* **NFR-05 安全与合规**：网关统一鉴权过滤，输入严格执行 XSS 净化，持久层全面预编译防止 SQL 注入。

## 5. 架构与工程约束

1. **统一前端约束**：前台、演练工作台、AI 对话抽屉与 Admin 后台全量统一在 Next.js 15 App Router 工程；
2. **阿里巴巴 Java 规范**：微服务代码遵循《阿里巴巴 Java 开发手册》，接口响应强制返回 `Result<T>`；
3. **单一可信源**：教研知识以 `docs/algorithms/` 为权威来源。
